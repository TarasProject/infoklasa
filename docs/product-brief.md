# Product Brief: Teacher Hub — сайт вчителя інформатики

## 1. Візія

Веб-платформа для вчителя інформатики, яка об'єднує:
навчальні матеріали, тести з автоперевіркою та завдання з прийомом робіт —
трьома мовами (українська, польська, англійська), з окремою адмін-панеллю
для вчителя.

Власник продукту й основний адміністратор — вчитель (одна людина),
розробка ведеться за допомогою AI-агентів (Project Factory), без окремої
команди підтримки. Це визначає всі рішення нижче: простота супроводу
важливіша за широту фіч.

## 2. Користувачі та ролі

- **Вчитель / Адміністратор** (наразі один — сам автор). Керує матеріалами,
  тестами, завданнями, класами, оцінками.
- **Учень**. Заходить під кодом класу або спрощеною реєстрацією, читає
  матеріали, проходить тести, здає завдання, бачить свої результати.
- *(На майбутнє, не зараз)* другий вчитель/асистент з обмеженими правами —
  варто закласти модель ролей так, щоб це можна було додати пізніше без
  переписування авторизації.

## 3. Ключові сценарії використання

1. Вчитель публікує урок (текст/файли/відео) трьома мовами — можна почати
   з однієї мови і додати переклад пізніше (матеріал не повинен "чекати"
   всіх трьох перекладів, щоб бути опублікованим).
2. Учень заходить, обирає мову інтерфейсу, знаходить матеріал за
   класом/темою, читає його.
3. Вчитель створює тест (кілька типів питань), призначає його класу з
   дедлайном; учень проходить тест, отримує результат одразу.
4. Вчитель публікує домашнє завдання з файлом-шаблоном; учень завантажує
   виконану роботу; вчитель перевіряє, ставить оцінку й коментар в
   адмінці; учень бачить оцінку у своєму кабінеті.
5. Вчитель дивиться загальний журнал: хто здав що, з якими оцінками, по
   класах.

## 4. Що навмисно поза межами MVP

- Відеоконференції / стрімінг занять наживо.
- Платежі / підписки.
- Мобільний застосунок (тільки адаптивний веб).
- Багатовчительська школа з окремими тарифами/білінгом.

Ці пункти можна винести в окремий backlog.md і не включати в перший
capability plan Project Factory — так простіше буде довести MVP до кінця.

## 5. Відкриті питання (варто вирішити до/під час Фази 0)

- Мінімальний вік учнів і чи потрібна згода батьків на збір навіть
  мінімальних персональних даних (ім'я, клас, email) — уточнити вимоги
  GDPR/RODO для школи.
- Формат входу учня: email+пароль, код класу без email, чи шкільний
  логін? Це впливає на схему Better Auth.
- Система оцінювання: чи потрібна лише "правильно/неправильно" для
  тестів, чи бали/ваги питань і підсумкова шкала (наприклад 1–6).
- Чи потрібен окремий домен/піддомен, чи достатньо *.vercel.app на старті.
