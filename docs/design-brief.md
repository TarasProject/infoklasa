# Design Brief — Teacher Hub

## Напрямок
Сучасний освітній мінімалізм: чисто, багато повітря, зрозуміла навігація
для учнів різного віку. Не "корпоративний SaaS", радше приємний навчальний
портал.

- Світла й темна теми, перемикання вручну + авто за системою.
- Типографіка: одна нейтральна sans-serif пара (наприклад Inter або
  системний stack) — легко читається трьома мовами, включно з
  кирилицею.
- Кольори: 1 акцентний колір (можна прив'язати до предмету —
  інформатика/код) + нейтральна сіра шкала для фону/тексту. Уникати
  великої кількості яскравих кольорів одночасно — учні дивляться на це
  щодня.

## Ключові екрани (мінімум для референсу)
1. Публічна головна / каталог матеріалів.
2. Сторінка матеріалу (урок з текстом, файлами, відео).
3. Проходження тесту (питання, таймер, кнопка "завершити").
4. Кабінет учня (оцінки, статуси завдань).
5. Адмін-панель вчителя (список матеріалів/тестів/завдань, форма
   створення).

## Рекомендований підхід (моя пропозиція, не лише текстовий опис)
Текстовий опис стилю — це нормально для старту, але для Project Factory
(і зокрема для його visual-fidelity перевірки — check-visual-fidelity.mjs,
Playwright, vision judge) значно ефективніше дати **візуальний референс**,
з яким агенти й перевірка зможуть звіряти результат, а не лише текст.

Два варіанти, можна поєднати:
1. **Референси-скріншоти**: 2–3 сайти/платформи, дизайн яких подобається
   (не обов'язково освітні) + короткий коментар, що саме подобається
   (типографіка? кольори? компонування карток?).
2. **Швидкий мокап заздалегідь**: попросити Claude згенерувати статичний
   візуальний мокап 2–3 ключових екранів (каталог, тест, адмінка) ще до
   запуску Project Factory. Це дає команді агентів конкретний "якір":
   вони будують під вже затверджений вигляд, а не вигадують дизайн і
   ризикують розійтися з очікуваннями.

Я можу зробити такий мокап (наприклад, каталог матеріалів + сторінка
тесту) як наступний крок — скажи, якщо це цікаво, і чи є вже сайти-
референси, які подобаються.

## Компонентна бібліотека
Tailwind CSS + shadcn/ui (як і запропоновано в первинному бриф) — це
узгоджується з рекомендацією "мінімум окремих сервісів" з NFR-5: готові
доступні компоненти, менше власного CSS для підтримки.
