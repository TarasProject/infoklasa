# ADR-0001: Технологічний стек

**Статус:** Прийнято (обрано користувачем 2026-09-23)

## Контекст
Початкова ідея проєкту (зафіксована раніше) — простіший статичний сайт на
React + Vite з контентом у JSON-файлах і react-i18next, без власного
бекенду. Нові вимоги (адмін-панель з реальним збереженням змін, тести з
фіксацією спроб, кабінет учня з оцінками, прийом файлів завдань) **вимагають
базу даних і автентифікацію** — статичного сайту вже недостатньо. Це
нормальна еволюція вимог, а не помилка попереднього рішення: попередній
план підходив для суто інформаційного сайту, новий — для інтерактивної
платформи.

## Розглянуті варіанти
1. **Next.js + Neon (Postgres) + Drizzle ORM + Better Auth + Vercel Blob**
   (запропоновано Project Factory за замовчуванням).
2. **Next.js + Supabase** (Postgres + Auth + Storage в одному сервісі) —
   менше окремих акаунтів/конфігурацій, компроміс: трохи менше гнучкості
   в auth-логіці.
3. Залишити React + Vite (статика) і додати окремий легкий бекенд —
   відкинуто: подвоює складність (два деплої, два репо) без переваг для
   соло-розробника.

## Рішення
Обрано **варіант 1**: Next.js (App Router, TypeScript) + Postgres (Neon) +
Drizzle ORM + Better Auth + Vercel Blob, деплой на Vercel.

**Обґрунтування:**
- Це типовий, добре задокументований стек для AI-агентів (Claude Code,
  Project Factory та подібні інструменти генерують під нього якісніший і
  передбачуваніший код, ніж під менш поширені комбінації) — важливо, бо
  розробка ведеться автономними агентами, а не вручну.
- Один деплой (Vercel), безкоштовні tier-и для Neon і Vercel Blob
  достатні для масштабу одного ліцею.
- Server Actions / API Routes у Next.js покривають всю потрібну
  бекенд-логіку без окремого сервера.

**Компроміс, який свідомо приймається:** це більше окремих сервісів
(Neon + Better Auth + Vercel Blob), ніж дав би Supabase "все в одному".
Якщо в процесі розробки конфігурація виявиться завеликою тягарем для
одноосібної підтримки — варіант 2 (Supabase) залишається запасним, і
перехід можливий без зміни фронтенду (Next.js залишається).

## Наслідки
- `SPEC.md`/`SKILLS.md` з попереднього (React+Vite) підходу застарівають
  і мають бути переписані під новий стек на Фазі 0 Project Factory.
- i18n-рішення: замість react-i18next (клієнтський) — `next-intl`,
  сумісний з App Router і SSR.
